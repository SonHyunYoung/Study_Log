## 2. 기능적 요구사항

### 2.1 사용자 인증 및 계정
| ID | 기능 | 요구사항 |
|:---|:---|:---|
| FR-01 | 회원가입 | 이메일, 비밀번호, 닉네임으로 계정을 생성한다. |
| FR-02 | 닉네임 제한 | 닉네임은 최대 15자까지만 입력이 가능하도록 제한한다. |
| FR-03 | 보안 정책 | 비밀번호는 8자 이상이며 대소문자, 숫자, 특수문자를 각각 최소 1자 이상 포함해야 한다. |
| FR-04 | 보안 저장 | bcrypt 라이브러리를 사용하여 비밀번호를 해싱하여 DB에 저장한다. |
| FR-05 | 로그인 | 로그인 성공 시 JWT 토큰을 발급하여 localStorage에 저장하며, 토큰은 14일간 유지된다. |
| FR-06 | 접근 제어 | 토큰이 없는 비인가 사용자가 보호 페이지 접근 시 로그인 페이지로 강제 리다이렉트한다. |

### 2.2 문제 등록 및 관리
| ID | 기능 | 요구사항 |
|:---|:---|:---|
| FR-07 | 문제 정보 조회 | 백준 문제 번호 입력 시 Solved.ac API를 통해 제목과 난이도(Tier)를 자동 조회한다. |
| FR-08 | 데이터 캐싱 | 조회된 정보는 캐시 테이블에 저장하여 외부 API 중복 호출을 방지하고 성능을 최적화한다. |
| FR-09 | 문제 등록 | 사용 언어, 문제 상태(SUCCESS/FAIL), 메모를 입력하여 풀이 기록을 저장한다. |
| FR-10 | 중복 등록 방지 | 이미 등록된 문제 번호 입력 시, 등록 버튼을 비활성화하여 중복 데이터를 원천 차단한다. |
| FR-11 | 페이징 처리 | 문제 목록 조회 시 가독성 향상을 위해 한 페이지당 8개의 데이터를 노출한다. |
| FR-12 | 목록 필터링 | 전체, 성공, 실패, 복습완료 상태별 필터링 기능을 제공한다. |
| FR-13 | 상세 조회 | 문제 카드 클릭 시 모달을 통해 등록된 제목, 난이도, 메모, 언어 등 상세 정보를 제공한다. |

### 2.3 오답 노트 및 복습 로직
| ID | 기능 | 요구사항 |
|:---|:---|:---|
| FR-14 | 오답 목록 추출 | 상태값이 FAIL인 데이터만 별도로 필터링하여 오답 노트 섹션에 노출한다. |
| FR-15 | 오답 복기 UI | 복습 모달 진입 시, 과거에 기록한 오답 이유를 상단에 참조용(Read-only)으로 노출한다. |
| FR-16 | 데이터 갱신 | 복습 완료 시 기존 오답 이유는 삭제하고, 새롭게 작성한 해결 방법으로 memo 컬럼을 업데이트한다. |
| FR-17 | 상태 전이 | 복습 내용 저장 시 문제 상태를 RETRY_SUCCESS로 변경하며, 오답 리스트에서 자동으로 제거한다. |
| FR-18 | 시각적 피드백 | 복습 완료 및 저장 버튼은 초록색(#2B8A3E) 테마를 적용하여 완료의 의미를 강조한다. |

### 2.4 대시보드 (통계)
| ID | 기능 | 요구사항 |
|:---|:---|:---|
| FR-19 | 요약 위젯 | 전체 풀이 수, 성공, 실패, 복습 완료 개수를 메인 상단에 실시간 집계하여 표시한다. |
| FR-20 | 난이도 분포 | 문제 난이도를 상(Tier 11+), 중(Tier 6-10), 하(Tier 1-5)로 구분하여 차트로 표시한다. |
| FR-21 | 언어 통계 | 가장 많이 사용한 프로그래밍 언어 비중을 집계하여 시각화한다. |
| FR-22 | 퀵 링크 | 가장 최근에 등록된 복습이 필요한 문제(FAIL) 3건을 리스트로 노출한다. |

## 3. 비기능적 요구사항

### 3.1 보안 및 설계 원칙
| ID | 요구사항 |
|:---|:---|
| NFR-01 | 인증은 JWT 기반으로 처리하며, 모든 요청 헤더에 토큰 검증 미들웨어를 적용한다. |
| NFR-02 | RESTful API 설계 원칙을 준수하여 엔드포인트를 구성하고 JSON 형식으로 응답한다. |
| NFR-03 | 데이터베이스는 MariaDB를 사용하며, 사용자와 문제 데이터 간의 참조 무결성을 유지한다. |
| NFR-04 | ON DELETE CASCADE 설정을 통해 회원 탈퇴 시 관련 풀이 데이터가 함께 삭제되도록 설계한다. |

### 3.2 환경 및 문서화
| ID | 요구사항 |
|:---|:---|
| NFR-05 | 서버 실행 환경은 Ubuntu 22.04 LTS 및 Node.js v18 이상을 기준으로 한다. |
| NFR-06 | 모든 소스 코드 및 설계 문서는 GitHub 레포지토리 내에서 마크다운(md) 형식으로 관리한다. |
| NFR-07 | 프론트엔드 UI는 불필요한 장식을 배제하고 텍스트 중심의 정갈한 디자인을 유지한다. |
