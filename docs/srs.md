# SRS (Software Requirements Specification)

## 기능적 요구사항

### 사용자 인증

| ID | 기능 | 요구사항 |
|----|------|----------|
| FR-01 | 회원가입 | 이메일, 비밀번호, 닉네임으로 계정을 생성한다 |
| FR-02 | 회원가입 | 이메일은 중복 등록이 불가능하다 |
| FR-03 | 회원가입 | 비밀번호는 8자 이상이어야 한다 |
| FR-04 | 회원가입 | 비밀번호는 bcrypt로 암호화하여 저장한다 |
| FR-05 | 로그인 | 이메일과 비밀번호로 로그인할 수 있다 |
| FR-06 | 로그인 | 로그인 성공 시 JWT 토큰을 발급하여 localStorage에 저장한다 |
| FR-07 | 로그인 | 로그인 성공 시 대시보드로 이동한다 |
| FR-08 | 로그인 | 인증 실패 시 구체적인 실패 이유를 노출하지 않는다 |
| FR-09 | 로그아웃 | 로그아웃 시 localStorage에서 JWT 토큰을 삭제한다 |
| FR-10 | 로그아웃 | 로그아웃 후 로그인 페이지로 이동한다 |
| FR-11 | 접근 제어 | 토큰이 없으면 보호 페이지 접근 시 로그인 페이지로 강제 이동한다 |

---

### 문제 관리

| ID | 기능 | 요구사항 |
|----|------|----------|
| FR-12 | 문제 등록 | 백준 문제 URL을 입력하여 문제를 등록할 수 있다 |
| FR-13 | 문제 등록 | URL 입력 시 사이트를 자동 감지하여 뱃지로 표시한다 |
| FR-14 | 문제 등록 | 백준 URL 입력 시 Solved.ac API로 제목/난이도를 자동 입력한다 |
| FR-15 | 문제 등록 | Solved.ac API 호출 결과는 DB에 캐싱하여 중복 호출을 방지한다 |
| FR-16 | 문제 등록 | Solved.ac API 호출 실패 시 제목/난이도를 직접 입력할 수 있다 |
| FR-17 | 문제 등록 | 정답/오답 여부를 선택한다 |
| FR-18 | 문제 등록 | 정답 선택 시 풀이 방식 입력창을 표시한다 |
| FR-19 | 문제 등록 | 오답 선택 시 틀린 이유 입력창을 표시한다 |
| FR-20 | 문제 등록 | 자료구조 태그를 다중 선택할 수 있다 |
| FR-21 | 문제 등록 | 사용 언어를 선택할 수 있다 |
| FR-22 | 문제 등록 | 동일한 URL의 문제는 중복 등록이 불가능하다 |
| FR-23 | 문제 목록 | 본인이 등록한 전체 문제 목록을 조회할 수 있다 |
| FR-24 | 문제 목록 | 상태(전체/정답/오답/복습완료)로 필터링할 수 있다 |
| FR-25 | 문제 목록 | 태그로 필터링할 수 있다 |
| FR-26 | 문제 목록 | 제목 키워드로 검색할 수 있다 |
| FR-27 | 문제 상세 | 문제 카드 클릭 시 상세 정보를 조회할 수 있다 |
| FR-28 | 문제 상세 | 상세 정보는 제목, URL, 사이트, 난이도, 상태, 메모, 태그, 언어를 포함한다 |
| FR-29 | 문제 수정 | 등록한 문제의 메모, 태그, 언어를 수정할 수 있다 |
| FR-30 | 문제 삭제 | 등록한 문제를 삭제할 수 있다 |
| FR-31 | 문제 삭제 | 삭제 전 확인 모달을 표시한다 |

## 비기능적 요구사항

### 보안

| ID | 요구사항 |
|----|----------|
| NFR-01 | 비밀번호는 bcrypt로 암호화하여 저장한다 |
| NFR-02 | 인증은 JWT 토큰 기반으로 처리한다 |
| NFR-03 | 토큰 만료 시 로그인 페이지로 이동한다 |
| NFR-04 | 로그인하지 않은 사용자는 보호 페이지에 접근할 수 없다 |
| NFR-05 | 사용자는 본인이 등록한 데이터만 조회/수정/삭제할 수 있다 |

### API 설계

| ID | 요구사항 |
|----|----------|
| NFR-06 | REST 원칙을 준수하여 API를 설계한다 |
| NFR-07 | API 응답은 JSON 형식으로 반환한다 |
| NFR-08 | HTTP 상태 코드를 적절하게 사용한다 |

### 문서화

| ID | 요구사항 |
|----|----------|
| NFR-09 | 모든 설계 문서는 GitHub md 파일로 관리한다 |
| NFR-10 | 기능 단위로 커밋하여 개발 이력을 관리한다 |
